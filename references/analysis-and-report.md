# 分析与报告

## 校准关口

一级固定四类；二三级名均≤5字、客观，每个三级有一句判定说明，输出JSON。用户明确等待校准就停。只要脚本不等于授权打标。后来要求探索报告可做初标，但保留“分析师初标待复核”，不伪造已校准。

## 正式统计

```bash
python3 <skill>/scripts/voc_statistics.py --input <project>/data/coded/coded_reviews.jsonl --out <project>/output/statistics --low-star-max 3
```

标准库脚本，输入按data-contract.md。默认拒绝待校准数据，不自动判断情感。输出：

| 文件 | 口径和n |
|---|---|
| top20_level3_sentiment.csv | 同source_id同三级完整路径计1次；n全部合格已校准评论，含确认无标签评论 |
| brand_level2_sentiment.csv | 同品牌对象内同source_id同二级路径计1次；n_brand该品牌对象全部合格评论，n_total总体；未知品牌单列 |
| low_star_defects.csv | 默认实际Amazon1–3星，实际经历＋具体缺陷＋负向/混合；n_low_star全部合格低星；分对象列示 |
| label_evidence.csv | 每次赋值保留source_id、完整原文、逐字摘录、对象、情感和来源 |
| statistics_metadata.json | 输入哈希、排除量、分母、来源和规则 |
| statistics.json | 三张表和元数据 |

同路径情感合并：正负并存或含混合→混合；单一正/负加中性→正/负；仅中性→中性。二级重新聚合去重，不累加三级数冒充评论数。

探索性“正向榜/痛点榜”可以同评论同主题两边各计一次，必须注明与正式互斥情感表不同，不拼成一个总数。多主题比例之和可超过100%。

负向不自动是缺陷；价格意见、愿望、建议、推测不是实际性能失效。Reddit不能用互动或语气代替低星。n=0输出空表头及n=0，不写“无缺陷”。未知品牌不猜测；缺证就说明不能做品牌胜负。

每个聚合单元保存全量source_id集合；TOP20、品牌交叉、低星表均可从记录回算，确保表格数值等于去重集合大小。图表和正文必须用同一份统计。

## 完整报告七部分

1. 一页纸总览：问题、核心样本、前三机会/痛点、下一步、限制及结论ID。
2. 数据说明：来源、地区确认程度、时间窗、目标、采集方式、实际覆盖、排除、去重、校准和完整性。
3. 正面热点与痛点排序：单位、n、重复与情感规则，低星缺陷单列。
4. 异常信号卡：信号、证据、可能解释、不能推断什么、验证行动，不无证据指控造假。
5. 用户画像：自述任务、场景、需求和取舍，可重叠；不编人口属性或占比。
6. 证据链：claim_id→全部source_ids→摘录→text_raw→原始文件/URL，不仅给2个示例。
7. 可视化：主题排序、情感交叉、星级分布、来源敏感性，选择有解释价值的图。

## 关键解释

主题情感不由星级决定；商家、本体、配件、Vine/非Vine、完整/截断应区分。频次不能直接当美区普及率或产品故障率；评论性能陈述不等同实测。用户国家不由英语推断。

## 检查与交付

逐条验证source_id存在、摘录逐字匹配、引文旁ID正确、统计成员数和分母正确、HTML锚点可解析。CSV/JSONL回读行数和原文。只证明格式通过不代表语义通过。

PDF/DOCX调用当期对应skill并逐页渲染；中文按字宽换行，检查溢出、重叠、缺字、图例、页码和引文。不能只检查第一页或提取文字。

HTML支持搜索source_id/原文/主题以及结论展开，尽量离线自包含。交报告、证据、统计、口径和复跑脚本；qa图片作检查用，不默认交付。打包排除旧zip、重复解压目录和敏感UI。

首页与最终答复区分初标/已校准及部分/完整覆盖；报告内容齐全不能写成采集全量。
